# GRAPHCAUSE 图纸检测工作台

面向新能源汽车零部件的工程图审查演示。选取样本或上传 PDF，选择图种并开始检测，点击结果查看图面证据，可逐页查看及导出 JSON。文件仅在本次请求内处理。

## 本机运行

使用 Python 3.9 或更高版本，在项目目录执行：

    python3 -m venv .venv
    .venv/bin/pip install -r requirements.txt
    .venv/bin/flask --app app run --port 8099

打开 http://127.0.0.1:8099 。

## 容器部署

将整个目录放到装有 Docker Compose 的 Linux 主机，在目录中执行：

    docker compose up -d --build
    docker compose ps

默认监听本机 8099，反向代理可指向 127.0.0.1:8099。要更换端口，请在第一次启动时设 PORT；若需要服务器网卡直接接受连接，可设 BIND_ADDRESS。停止使用 docker compose down。

## 规则及样本

samples/reference.pdf 为正常图纸，10 项检查全部通过。samples/revision.pdf 为异常图纸，4 个常规异常（Logo 缺失、图号冲突、设计栏空白、日期无效）及 2 个技术异常（局部 Φ58 H8 与主视图 Φ58 H7 冲突、局部 Ra3.2 与技术要求 Ra1.6 冲突），其余 4 项通过。文件名不参与判断。

检查项共 10 项，包括 Logo、名称、图号、设计、日期、版本、签审、页码，以及轴承孔配合标注一致性、配合面粗糙度一致性。profile.json 配置编号、版本、日期、团队名、Logo 参考图、单位、必须审核的状态。替换图标时使用相同裁切范围的灰度参考图。重启服务后生效。

当前图框适配 GRAPHCAUSE 矢量 PDF，图种选择用于材料和单位的适用性判断。依据不足以识别图框时整页列为待复核。图框坐标及解析器在 inspect_pdf.py，其他版式需适配并用样本验证。文件上限 12 MB，页数上限 8。规则检查图面信息完整性和一致性。

检测完成后默认显示本页异常的编号和证据框。点编号可定位到报告条目，点条目可放大图纸，查看全图可复位。异常标记开关可用于对照原图。

特殊标记异常依据同一特征在主视图、局部视图和技术要求中的一致性判定。每条结果同时标出实际读取的两个数值及对应证据框。当前这两项比对适配本案例图框。

客户展示页在 /static/compare.html，可逐项对照六处正常与异常的原图证据、原因和修改建议。

## 客户演示

启动后访问首页进行单图检测，访问 `/static/compare.html` 查看正常图和异常图的六处对照。点击异常条目或图面编号可定位并放大证据。

- [商业推介汇报](客户演示/图因智检_工业质量智能系统_商业推介汇报.pptx)共 9 页，第 6 页并排展示全部六处差异及原因。
- [商业推介白皮书](客户演示/图因智检_工业质量智能系统_商业推介白皮书.docx)共 7 页，说明技术方案、规则、试点交付与验收。
- [图纸正反样本演示](客户演示/图纸正反样本_客户演示.pptx)用于讲解图纸案例。

当前演示通过矢量 PDF 解析、图框区域定位、参考图形比对及确定性规则运行，无需模型 API 密钥。宣传材料中的多模态视觉模型属于平台方案，客户项目需另行接入并验证。
